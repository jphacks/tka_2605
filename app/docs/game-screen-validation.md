# ゲーム画面の実装・検証

2026-10-18（日本時間）時点。

## 実装した範囲

- JSONに基づくopening・調査導入・人物別証言・結果の画像と台詞、AR調査、endingの選択・正誤判定、クリア表示。
- ホストによる台詞送り・途中タップでの全文表示の同期、各段階の両者収集完了後の手動進展。
- 更新JSONのStory別証拠IDに従う3段階の調査進行。各段階は両者の完了待ちとし、現在の対象Entityだけを配置する。
- 同じARViewを保持した9:16 / 1:1切り替え、撮影、キャンセル、証拠モーダル、自己・合計カウント。
- RealityKitのComponent / Systemによる分類別の順次配置、認識面の範囲と中心間1mの検証。
- 実モデルの三角形メッシュの表面まで30cmの判定、画面外・距離超過・追跡中断による選択解除。
- JSON指定のUSDZ（10資産を12証拠で使用）、通常の最長辺20cm・足跡の全長約3.33m（5mの2/3）への正規化と中心・向きの調整、非同期読み込み、調査切り替え後の古い読み込み結果の除外。書類・本はTable、小箱はFloorへ配置する。
- 資産ごとの正面・上方向の補正、水平面での立体物の直立と配置時カメラ方向への整列、紙・シミ・足跡の面への整列。配置後のカメラ移動で向きは変えない。
- 探索10秒での未取得証拠の再設置提案、自作確認ダイアログ、取得済み・撮影済みで同期待ちの証拠の保護。ARセッションは維持し、近い認識面を優先してECSで配置を再探索する。
- 初回失敗後のモデル読み込み再試行、面更新がなくても継続する配置再探索、候補ごとの向きでの収まり判定、未取得モデル同士の配置組み合わせの再検討。画面には未配置の証拠ごとに面認識・範囲・間隔の待機理由を表示する。
- モデルを含みUIを含まないAR写真、端末内保存、最新写真への置き換え。リソース名が空の場合のみ従来の札を表示する。
- ホスト確定の共有状態、操作の担当・フェーズ検証、収集重複の排除。
- 同じ相手との再接続、確定状態との照合、未確認の収集・提出の再送、写真の保持。
- endingの試行番号による古い提出の排除、誤答時の人物・両者の証拠リセット。
- 人物の証言を読み終えた後の提示・人物選択への戻り、誤答回数と人物の選び直しの区別、結果ストーリー読了後のクリア画面。

追加の確定仕様は [story-spec.md](story-spec.md) を参照。調査中の証拠モーダルから村人へ話を聞く機能と、アプリ終了後の復元は後回し。

## 実機2台で残る確認

1. 同じビルドを2台へ入れ、ホストがエピソードを選択。接続・状態同期後に開始でき、ゲストもopeningへ進むこと。
2. ホスト操作でopening・初回調査の台詞を読み、2人がAR調査へ進むこと。文字送り中のタップで2人とも全文を表示し、次のタップで同じ台詞へ進むこと。ホストに人的証拠、ゲストに物的証拠だけが配置されること。
3. 各証拠の指定分類と認識した面が一致するまで配置されず、狭い面・面の更新でもモデル全体の包含と中心間1mが保たれること。モデルの向き・マテリアルも確認する。各段階の両者完了後、ホストの進展操作で次の台詞とStoryの証拠へ切り替わり、読み込み中の旧モデルが遅れて現れないこと。
4. 撮影画面が1:1になり、画面内のモデルの表面まで30cm以内でタップした場合だけシャッターが有効になること。離れる・画面外に出る・追跡中断で解除されること。スタンドライト等の空洞部分をタップしても選択されないこと。
5. 保存写真がカメラ映像とARモデルを含み、操作UIを含まないこと。撮影後は探索へ戻り、モデルが残り、再撮影で写真だけが置き換わること。
6. 証拠モーダルには自分の撮影済み証拠だけが表示され、自己・合計カウントが両端末で一致すること。
7. 途中で通信を切断し、操作が止まること。同じ相手に復帰すると写真・配置・フェーズ・未確認操作が保持されること。
8. 最後の証拠をほぼ同時に撮影した場合も、ホストの進展操作を待つこと。進展時にゲストの証拠モーダルが開いていても、閉じて2人がendingへ移行すること。
9. ホストの人物確定後に当人の証言だけを表示し、読了後に提示か人物選択へ戻る操作を選べること。提示後は各自が証拠を選べ、誤答で両者リセット、正答で結果の台詞をすべて読んでからクリア画面へ進むこと。
10. 探索を10秒続けると再設置提案が表示されること。キャンセルでは位置が変わらず、確定では未取得の証拠だけが近い面から再配置され、取得済みのモデル・写真と認識面が維持されること。条件を満たす場所がなければ待機すること。

ARの配置精度・距離精度と2台間の実通信は未検証。ビルド・自動テストの成功とは分けて扱う。

`Window` 必須の証拠で「窓をゆっくり映して認識させてください」が続く場合は、Xcodeコンソールで `AR plane classifications:` を確認する。`Surfaces` カテゴリに、分類別の平面アンカー数を変化時だけ出力する（例: `wall=2, window=0`）。`window=0` の間は再設置しても窓への配置候補がない。`Window` を `Wall` へ読み替えず、分類が得られるまで待機する。ログの数は実物の窓の枚数ではなく、ARKitの平面アンカー数。
