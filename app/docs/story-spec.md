# ストーリーの表示と進行

2026-10-18（日本時間）にユーザーと確認した追加仕様。
調査・通信・写真保存の基本仕様は [game-screen-spec.md](game-screen-spec.md) を参照。
ストーリーと進展のタイミングについては、この文書を優先する。

## データと共通画面

- `EpisodeData.json` の `stories` の順序と、参照する `StoryData.json` の `tag`・`turn`・証拠IDに従う。画面に台詞やストーリーIDを固定しない。
- `turn.resourceName` の2D画像を中央に縦横比を保って表示し、`statement` を下部の台詞枠に表示する。
- 話者名は `personID` に対応する人物の名前。`personID: 0` のナレーションでは名前を隠す。
- 台詞は文字送りで表示する。途中で台詞枠をタップすると全文表示、全文表示後のタップで次へ進む。
- 台詞枠を操作できるのはホストだけ。全文表示の指示と次の台詞への移動を2台で共有する。ゲストには待機案内を表示する。
- 文字送り自体は各端末で行う。Reduce Motion・VoiceOver利用時は全文を表示する。
- 接続が失われた場合は操作と文字送りを止め、再同期した台詞位置から再開する。
- 画像が未配置でも進行できるよう画像枠を表示する。画像はAssetsまたはアプリバンドルへ `resourceName` と一致する名前で追加できる。

## オープニングと調査

現行JSONの進行順は以下。

```text
ロビーから開始
  → オープニング（id: 0）
  → 調査1の台詞（id: 1）→ 探索1
  → 両者の対象証拠が揃う → ホストの「ストーリー進展」
  → 調査2の台詞（id: 2）→ 探索2
  → 両者の対象証拠が揃う → ホストの「ストーリー進展」
  → 調査3の台詞（id: 3）→ 探索3
  → 両者の対象証拠が揃う → ホストの「ストーリー進展」
  → エンディングの人物選択
```

- 各調査の `personalEvidences` 全件をホスト、`physicalEvidences` 全件をゲストが取得すると進展可能になる。
- 取得完了だけでは次の調査・エンディングへ移らない。ホストにだけ進展ボタンを表示し、ゲストには待機案内を表示する。
- 各調査の台詞を読み終えると探索へ戻る。ストーリー画面を任意に閉じる操作は設けない。
- ストーリー表示中はAR操作・撮影・探索時間の計測を止める。同じゲームのAR空間と撮影写真を保持する。

## エンディング

1. ホストが証言を聞く人物を選択する。ナレーションは対象外。
2. `truth_uncovering_phase`（現行id: 4）のうち、その人物の `personID` に一致する台詞だけを元の順番で再生する。
3. 証言を最後まで読んだ後、ホストが「証拠を提示する」または「人物選択に戻る」を選ぶ。
4. 提示を選ぶと2人とも証拠選択へ移り、各自が担当の証拠を1つずつ確定する。
5. 両者の提出が揃った時点で、人物・人的証拠・物的証拠をJSONの正解IDと照合する。
6. 不正解なら案内を表示して人物選択から再挑戦する。回数制限なし。
7. 正解なら `result_phase`（現行id: 5）をすべて再生してから、クリア画面と「タイトルへ戻る」を表示する。

- 証言の途中では証拠を提示できない。
- 提示せず人物選択に戻る操作は不正解として数えない。別の人物の証言も聞ける。
- 人物の選び直しごとに試行番号を更新し、前の試行に対する提出を拒否する。
- 該当人物の台詞が未設定の場合は、証言後の選択へ進む。
- 調査中の「村人に話を聞く」は今回のストーリー進行には含めない。

## 同期と検証

- ホストが台詞位置・全文表示指示・証言後の段階を確定し、既存のスナップショットで配信する。
- 台詞ごとに識別子を更新し、前の台詞への遅れたタップを反映しない。
- ストーリー表示中の撮影保存・証拠取得や、証言読了前の証拠提出を状態更新側でも拒否する。
- 共有状態の往復、進展条件、人物別証言、提示・再選択・正誤判定、結果ストーリー、再接続と写真保持は `bash tests/run-game-rules.sh` で検証する。
- 実機2台での文字送り・タップの体感、切断復帰、ストーリーとARの切り替えは別途確認が必要。
